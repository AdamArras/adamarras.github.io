What is Quarto?

Here is how to create and publish an academic website online in 30 minutes.

I recently moved my academic website from Jekyll to Quarto. Both are Markdown-based static site generators, but Quarto is better suited to academic use, with built-in support for citations and integration with R, Python, and Julia.

This post outlines the minimal steps required to create and publish a personal academic website using Quarto and GitHub Pages. Once the basic site is in place, you can progressively refine its structure and appearance using the official documentation linked at the end of the post.

Overview

There will be three main steps:

  1. Create a local Quarto website.
  2. Customize the content and style.
  3. Publish the website using GitHub Pages.

You will need a terminal, Quarto, and a GitHub account.

Step 1: Create a local Quarto website

Install Quarto

First, check that Quarto is correctly installed. If not, download and install it from: quarto.org

Create a website project

From a terminal, navigate to the directory where you want to create your website and run:

quarto create-project academic-site --type website
cd academic-site

This command generates a basic Quarto website structure.

If you prefer not to use the terminal, you can download the minimal template used in this post:

Download the website (ZIP)

After unzipping the archive, you can start working immediately inside the resulting directory.

Understanding the files

The folder academic-site consists of four files, each with a distinct role:

  • _quarto.yml — Site configuration
    This file defines the global structure and behavior of the website, including the site title, navigation bar, theme, table of contents, and output format. It is written in YAML (which stands for Yet Another Markup Language) and is the central configuration file that Quarto reads when rendering the site.

  • styles.css — Custom styling
    This file allows you to override or extend the default Quarto theme using CSS. It is useful for adjusting typography, spacing, colors, and other visual elements without modifying the theme itself.

  • .qmd — Quarto pages
    The remaining two files are .qmd files. The extension .qmd stands for Quarto Markdown: q for Quarto and md for Markdown. These files define the content of the website pages.

    • index.qmd is the main landing page of your website. It typically contains a short introduction and other information that visitors should see on the first page.

    • about.qmd is an example of an additional page linked directly from the navigation bar. You can later add other pages (for example, research.qmd, publications.qmd, or teaching.qmd) in the same way.

Preview the site locally

To preview the website during development, run:

quarto preview

Make sure you are in the project root directory. This command starts a local development server that automatically rebuilds the site when files change. You can then view the website in your web browser.

If you prefer not to use the terminal, you can preview the site from an editor such as VS Code (with the Quarto extension) or RStudio. These editors provide buttons to render or preview the website, but they internally run the same quarto preview command.

Both macOS and Windows include a built-in terminal, which is sufficient to run the Quarto commands shown in this tutorial.

Step 2: Customizing the style

Configuration file

We start with the site configuration file, _quarto.yml, which controls:

  • the overall site structure
  • global metadata (title, description)
  • navigation, theme, and layout options

Personalizing site identity (metadata & favicon)

Set your site identity early:

website:
  title: "Nom Prénom"
  description: "Research, teaching, and notes"
  favicon: favicon.png

The title appears in browser tabs and often in search results, while the description may be used by search engines. The favicon improves recognizability when multiple tabs are open. Use a small, simple image—typically a 32×32-pixel PNG of your initials.

Navigation bar as an information hierarchy

The ordering of the navigation bar reflects what you want visitors to find first:

navbar:
  left:
    - text: Home
      href: index.qmd
    - text: Research
      href: research.qmd
    - text: Teaching
      href: teaching.qmd
    - text: Notes
      href: notes.qmd
    - text: About
      href: about.qmd

The order of the entries here determines their order in the navigation bar. Each href must correspond to an existing .qmd file. For this reason, it is good practice to create placeholder pages immediately. From a terminal, run:

touch research.qmd teaching.qmd notes.qmd

Alternatively, you can simply create files with these names using your editor.

A minimal template for a new page is:

---
title: "Research"
toc: false
---

Content coming soon.

Every page should start with YAML front matter, even if minimal. In particular:

In practice:

  • Set toc: false for short pages (Home, About)
  • Set toc: true for long pages (Notes, Research)

Refresh the website

After editing _quarto.yml, changes may not be picked up reliably by the preview server. In that case, stop the server (press Ctrl+C in the corresponding terminal), restart it by running quarto preview, and then refresh the page in your web browser.

Custom styling (styles.css)

The CSS file deals with the presentation: how things look, fonts, spacing, colors and small layout refinements. Theme defaults can be overridden using CSS:

h1, h2, h3 {
  font-family: "Georgia", serif;
}

.navbar-title {
  font-weight: bold;
}

Afterward, refresh the Quarto preview.

Step 3: Publish the website with GitHub Pages

We will use GitHub Pages to deploy the website online. This solution has several advantages. It is free and reliable. One limitation is that the website URL will be of the form username.github.io.

Quarto websites can be published on GitHub in two main ways: either by rendering the site locally and serving the generated files via GitHub Pages, or by letting GitHub Actions render and deploy the site automatically. Although I personally use the second option, this post presents the first approach for its simplicity.

Create a GitHub repository

On GitHub, create a new repository (for example, academic-site). Do not initialize it with a README.

Configure Quarto to publish from main

Edit the file _quarto.yml and ensure the following configuration is present:

project:
  type: website
  output-dir: docs

This tells Quarto to render the website into the docs/ directory, which GitHub Pages can serve directly from the main branch.

Push your project to GitHub

From the root directory of your website project, run:

git init
git add .
git commit -m "Initial Quarto website"
git branch -M main
git remote add origin https://github.com/USERNAME/academic-site.git
git push -u origin main

Replace USERNAME with your GitHub username.

At this stage, both the Quarto source files and the rendered website (in docs/) are stored on GitHub.

Enable GitHub Pages

On GitHub:

  1. Open the repository Settings
  2. Go to Pages
  3. Under Source, select:
    • Branch: main
    • Folder: /docs
  4. Save

GitHub Pages will now serve the website directly from the docs/ directory.

Updating the website

At this point, the basic academic website is fully set up. Further customization can be done incrementally by consulting the following resources:

  • Quarto website gallery
  • Modifying the Default Quarto Blog Structure

After modifying the content of the site, run the following commands in a terminal from inside the academic-site folder:

quarto render
git add docs
git commit -m "Update website"
git push

After pushing changes to the main branch, the website is rebuilt and published automatically.
